# استقرار اصلاحات همسان‌سازی پنل — ۱۷ اکتبر ۲۰۲۶

این تغییرها روی شاخهٔ توسعه آماده شده‌اند؛ هنوز روی هاست نصب نشده‌اند. پروژهٔ وب پیش از ویرایش با `origin/main` همگام شد. تغییر دیتابیس، کلاس جدید قابل autoload، تغییر پیکربندی یا migration لازم نیست.

## فایل‌های اجرایی لازم برای آپلود

همهٔ فایل‌های زیر باید از همین نسخه و به‌صورت یک مجموعه منتشر شوند:

- `Modules/Analytics/Controllers/Web/AdminDashboardController.php`
- `Modules/Analytics/Services/AdminDashboardService.php`
- `Modules/Analytics/Services/MobilePanelCatalog.php`
- `Modules/Analytics/Routes/routes.php`
- `Modules/Analytics/Resources/mobile-panel-presentation.php`
- `Modules/Analytics/Resources/Views/sections/sidebar.php`
- `Modules/Analytics/Resources/Views/sections/reports.php`
- `assets/Analytics/js/reports.js`
- `assets/Analytics/js/report-templates.js`

فایل‌های آزمون و runner برای Git/CI هستند و برای اجرای سرویس لازم نیستند: `scripts/panel_report_snapshot_test.php`، `scripts/panel_report_source_test.cjs`، تغییرات `mobile_panel_presentation_test.php`، `panel_sidebar_navigation_test.php` و `run-release-tests.cjs`.

## تغییر رفتار

- ستون شناسهٔ اضافهٔ قرارداد عمومی موبایل حذف شد؛ شناسه‌های داخلی رکوردها همچنان برای درخواست مجاز API حفظ می‌شوند. شمارهٔ ردیف تاریخچهٔ امتیازها حفظ شده است.
- شخص مالک آموزشگاه بدون نقش/قرارداد جداگانه، منوی سازمانی متناظر با قابلیت مدیریت مجاز خود را می‌بیند. این تغییر مجوز نوشتن جدیدی در سرویس‌های سازمانی نمی‌دهد.
- مسیر جدید `GET /analytics/admin-reports` از سرویس موجود داشبورد و همان محدودیت شعبه‌ها استفاده می‌کند؛ `academy-panel` و مجوز کاتالوگ موبایل حفظ شده‌اند.
- گزارش‌های تصادفی وب و شعبه‌های نمونه حذف شدند. چهار خلاصهٔ زندهٔ واقعی جای آن‌ها را گرفته‌اند: حضور ماه جاری، درآمد ماه جاری، ثبت‌نام هفت روز اخیر و وضعیت جاری. بازهٔ ماه، مطابق query فعلی داشبورد، ماه میلادی است. این فهرست آرشیو تاریخی یا گزارش سالانهٔ ساخته‌شده از دادهٔ واقعی نیست؛ فیلتر فاقد گزارش نتیجهٔ خالی دارد.
- گزارش شعبهٔ آموزشگاه به‌تنهایی ساخته نمی‌شود؛ سرویس داشبورد فعلی دامنهٔ شعبه‌ها را پشتیبانی می‌کند. فیلتر گزارش وب/اپ فقط شعبه‌های مجاز و «همه» دارد. دادهٔ ساختگی برای پرکردن این خلأ اضافه نشده است.
- تغییر فیلتر شعبه دادهٔ قبلی را پاک می‌کند؛ پاسخ قدیمی درخواست هم‌زمان جای پاسخ دامنهٔ جدید را نمی‌گیرد. خروجی فیلتر خالی به کل ردیف‌ها بازنمی‌گردد.

گزارش‌ها و گالری نمونهٔ نمودار همچنان شرط نمایش محیط محلی منوی موجود را دارند؛ برای کاربران محیط production منوی جدیدی فعال نشده است.

## ترتیب انتشار و بازگشت

۱. از فایل‌های بالا نسخهٔ بازگشت بگیرید؛ تنظیمات، داده‌ها و رسانه‌های محیط را حفظ کنید.
۲. فایل‌های وب را یکجا منتشر کنید و در صورت فعال بودن، OPcache و کش دارایی‌های همان نسخه را تازه کنید.
۳. بررسی کنید کاتالوگ جدید `reports` را به `/analytics/admin-reports` و مجموعهٔ `reports` متصل می‌کند و ستون‌های قرارداد بدون شناسهٔ اضافه‌اند.
۴. سپس نسخهٔ اپ دارای تغییرات `panel_*` را منتشر کنید. ساخت خروجی اپ در این کار انجام نشده است. APIهای قدیمی حذف نشده‌اند؛ نسخه‌های قبلی همچنان مسیرهای قبلی خود را دارند.

برای بازگشت، مجموعهٔ همین نه فایل را از نسخهٔ پیشین بازگردانید؛ تغییر داده‌ای یا migration معکوس لازم نیست. بازگشت وب، منبع گزارش قدیمی نمونه‌ای را هم بازمی‌گرداند؛ آن را گزارش واقعی تلقی نکنید. نسخهٔ جدید اپ برای دریافت گزارش جدید به API جدید نیاز دارد.

## آزمون کوتاه پس از آپلود

- با مالک شخصی آموزشگاه، مدیر/پذیرش و حساب شعبه، منو و دامنهٔ شعبه‌ها را مقایسه کنید؛ با کاربر عادی مسیر سازمانی باید رد شود.
- درخواست گزارش با شعبهٔ غیرمجاز باید رد شود و نباید ردیف یا اطلاعات شعبهٔ دیگر برگردد. مقدار گزارش باید با داشبورد همان حساب و همان شعبه برابر باشد.
- در محیط محلی مجاز، تغییر سریع شعبه، نتیجهٔ خالی، خطای شبکه و خروجی فیلتر خالی را بررسی کنید؛ شاخص‌ها و عنوان‌های واردشده توسط کاربر باید escape شوند.
- در اپ، ۱۱ ردیف و یک مجموعهٔ چندصفحه‌ای را مرتب و صادر کنید؛ Excel باید XLSX واقعی با ستون‌های همان نقش باشد. تقویم هفتگی باید روزهای شنبه تا جمعه و همهٔ جلسات روز را دریافت کند.
- دکمهٔ تأیید لغو برای پذیرش فاقد مجوز ظاهر نشود؛ فقط نخستین قسط پرداخت‌نشده عملیات پرداخت داشته باشد. رد مجدد سرور را نیز با درخواست مستقیم بررسی کنید.

fixtureهای محلی جای آزمون MySQL، مرورگر واقعی، دستگاه، درگاه و حساب‌های واقعی را نمی‌گیرند. چک‌لیست نقش‌به‌نقش در مستند اپ، بخش ۱۲، موارد باقی‌مانده را مشخص می‌کند.
