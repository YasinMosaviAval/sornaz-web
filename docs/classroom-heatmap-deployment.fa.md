# نقشهٔ حرارتی پر و خالی کلاس‌ها

این قابلیت در بخش «کلاس‌ها»ی وب و هر دو worktree فلاتر توسعه و انتشار اضافه شده است. جدول روز هفته × ساعت، تعداد کلاس‌های در دسترس دارای رزرو هم‌پوشان را برای هفتهٔ انتخاب‌شده نشان می‌دهد. هفته از شنبه شروع می‌شود. انتخاب تاریخ، هفتهٔ قبل/بعد، انتخاب یک کلاس، تمام فیلترهای فهرست کلاس‌ها، دامنهٔ رنگ، تم، فارسی/انگلیسی و خروجی PNG پشتیبانی می‌شوند. تاریخ هفته در تصویر خروجی درج می‌شود.

## معنی شمارش

- هر کلاس در هر ساعت فقط یک‌بار شمرده می‌شود؛ چند جلسهٔ هم‌پوشان یک کلاس ظرفیت اشغال را چندبرابر نمی‌کنند.
- شروع ساعت شامل و پایان آن غیرشامل است؛ جلسهٔ ۹:۳۰ تا ۱۱ در ساعت‌های ۹ و ۱۰ حساب می‌شود.
- «بدون رزرو» برابر تعداد کلاس‌های در دسترس مطابق فیلتر منهای کلاس‌های پر همان سلول است و در راهنمای سلول دیده می‌شود. مقدار صفر سلول، یعنی هیچ کلاس در دسترسی در آن ساعت رزرو ندارد.
- کلاس خارج از دسترس یا در انتظار، در ظرفیت قابل شمارش پر/بدون رزرو قرار نمی‌گیرد و تعدادش جدا ذکر می‌شود. تعطیلی، ساعت کاری، تجهیزات موردنیاز و سایر شرایط رزرو در این نمودار ارزیابی نمی‌شوند؛ بدون رزرو تضمین امکان رزرو نیست.
- رزروهای در انتظار نیز زمان را نگه می‌دارند؛ رزروهای لغوشده و ردشده و جلسه/رزرو/ترم حذف‌شده کنار گذاشته می‌شوند. این رفتار با قاعدهٔ فعلی `ScheduleGuard` هماهنگ است.
- آمار از همهٔ کلاس‌های مطابق فیلتر، پیش از صفحه‌بندی محلی، ساخته می‌شود. هفتهٔ بدون رزرو یک شبکهٔ صفر دارد؛ خطای API آمار قدیمی یا دادهٔ صفحهٔ فعلی را جایگزین نمی‌کند.

## API و دسترسی

`GET /academy/admin/classrooms/heatmap?week=YYYY-MM-DD` و معادل موبایل آن `GET /api/sornaz/v1/panel/classrooms/heatmap?week=YYYY-MM-DD` اضافه شده‌اند. پاسخ شامل `weekStart`، `weekEnd` و `heatmap` است. هر ردیف خلاصه فقط `classroomId`، `date`، `startTime`، `endTime` و `count` دارد؛ اطلاعات اشخاص ارسال نمی‌شود.

تاریخ نامعتبر رد می‌شود. محدودهٔ شناسهٔ کلاس از `AcademyClassroomService::scopedRooms` و همان سازمان‌های مجاز فهرست کلاس‌ها استخراج می‌شود؛ شناسهٔ ارسالی کاربر مبنای مجوز نیست. SQL فقط رزروهای این شناسه‌ها در همان هفت روز را می‌خواند. middleware پنل و احراز هویت bearer موجود حفظ شده‌اند. کاربر عادی به API مدیریتی دسترسی ندارد.

فیلتر و انتخاب کلاس محلی است و درخواست شبکهٔ اضافه ندارد؛ تعویض هفته یا تازه‌سازی پاسخ کامل همان هفته را می‌گیرد. پاسخ دیرهنگام هفتهٔ قبلی کنار گذاشته می‌شود. اپ در نبود action جدید، پیام نیاز به به‌روزرسانی API نشان می‌دهد.

## فایل‌ها و ترتیب انتشار وب

۱. فایل جدید `assets/Analytics/js/classroom-heatmap.js` و نسخهٔ جدید `assets/Analytics/js/schedule-heatmap.js` ابتدا روی سرور حاضر شوند. فایل دوم renderer مشترک دو نمودار است و نام توابع قبلی تقویم را حفظ می‌کند. وابستگی جدیدی نصب نشده و ECharts و `SornazCharts` موجود استفاده می‌شوند.

۲. به ترتیب سرویس، کنترلر و مسیرهای زیر منتقل شوند:

- `Modules/Academy/Services/AcademyClassroomService.php`
- `Modules/Academy/Controllers/Web/AcademyClassroomController.php`
- `Modules/Academy/Routes/web.php`

۳. سپس کاتالوگ و رابط زیر منتقل شوند؛ انتشار اتمی مجموعه ترجیح دارد. کاتالوگ تنها پس از آماده‌شدن مسیر جدید منتشر شود:

- `Modules/Analytics/Services/MobilePanelCatalog.php`
- `assets/Analytics/js/classrooms.js`
- `Modules/Analytics/Resources/Views/sections/classrooms.php`
- `Modules/Analytics/Resources/Views/layouts/admin.php`
- `docs/panel-assets-upload.sha256` برای بررسی فایل‌ها

نسخهٔ اصلی `schedule-heatmap.js` با تقویم قبلی سازگار است. بارگذاری layout پس از آماده‌شدن renderer و فایل جدید انجام شود. نسخه‌گذاری محتوایی دارایی‌های فعلی تغییر کش را پوشش می‌دهد. migration، تنظیم محیطی، مجوز جدید، کلاس PHP جدید یا بازسازی autoload لازم نیست. اسکریپت‌ها، لاگ آزمون و دادهٔ fixture در بستهٔ عادی سرور نیستند. تنظیمات و دادهٔ واقعی سرور حفظ شوند.

## آزمون و بازگشت

آزمون SQL روی SQLite واقعی با دادهٔ ساختگی، محدودهٔ شناسه‌های مجاز، هفته، نگه‌داشتن رزرو در انتظار، حذف لغوشده/ردشده/حذف‌شده و تاریخ نامعتبر را بررسی می‌کند. این fixture تأیید یکپارچهٔ MySQL اصلی نیست. آزمون مرورگر از ECharts واقعی در فارسی/انگلیسی استفاده می‌کند و شمارش یکتا، کلاس خارج از دسترس، تمام صفحات، فیلتر، انتخاب کلاس، هفتهٔ صفر، خطا، موبایل، تم تاریک و PNG را می‌سنجد. آزمون نمودار قبلی تقویم نیز اجرا می‌شود. آزمون فلاتر شمارش، هفته، فیلتر بدون درخواست اضافه، رقابت پاسخ‌ها، API قدیمی و بایت‌های PNG را پوشش می‌دهد.

برای بازگشت، مجموعهٔ فایل‌های وب و اپ به نسخهٔ قبل بازگردد؛ پیش از حذف مسیر، action کاتالوگ غیرفعال شود. داده و schema برای این قابلیت تغییر نکرده است. فایل جدید بدون ارجاع می‌تواند باقی بماند.

پس از انتشار روی سرور تست: با دو حساب از آموزشگاه‌های متفاوت، یک هفتهٔ دارای رزرو و یک هفتهٔ خالی بررسی شود؛ انتخاب کلاس، فیلتر، PNG و رد دسترسی کاربر غیرمجاز آزموده شود. برای تأیید نهایی انتشار اپ، ساخت تازه و آزمون روی دستگاه واقعی لازم است.

نتیجهٔ بررسی محلی: هر ۱۱۰ مجموعهٔ آزمون انتشار وب موفق شد. در توسعه و انتشار فلاتر، هر کدام ۵۱ آزمون مرتبط موفق شدند. بررسی نحوی PHP/JavaScript و `git diff --check` موفق است. بررسی نگهداری کل PHP همچنان بدهی‌های قبلی مخزن را گزارش می‌کند و تأیید کامل این بررسی ادعا نمی‌شود؛ baseline افزایش داده نشده است.
