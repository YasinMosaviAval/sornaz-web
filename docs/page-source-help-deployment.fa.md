# منابع سازندهٔ صفحه در راهنمای مدیر

فقط حساب `user_id=1` نام نسبی فایل‌های پروژه و نقش هر فایل را در دیالوگ راهنما می‌بیند. قالب‌های همان بخش، زیرقالب‌ها، فایل‌های مشترک PHP، اسکریپت‌ها و استایل‌ها، و فایل‌های درخواست‌های JSON مشاهده‌شده جدا نمایش داده می‌شوند. فایل‌های درخواست داده پس از اجرای درخواست اضافه می‌شوند. در پنل چندبخشی، فایل‌های مشترک سند ممکن است متعلق به چند بخش باشند. مبنای این فهرست بارگذاری فایل است، نه اجرای تک‌تک متدها یا فهرست تمام کتابخانه‌های نصب‌شده.

مسیر مطلق، محتوای فایل‌ها و مسیرهای PHP مربوط به config، storage، vendor و Lib ارسال نمی‌شوند. متادیتای JSON فقط با هدر `X-Sornaz-Source-Trace: 1` و تأیید سمت سرور برای حساب شمارهٔ ۱ افزوده می‌شود؛ فیلدهای معمول پاسخ حفظ می‌شوند. هدر جعلی از سایر حساب‌ها مؤثر نیست. پاسخ دارای متادیتا `private, no-store` است. پاسخ‌های JSON که مستقیماً خارج از پاسخ‌سازهای استاندارد نوشته شوند، متادیتای درخواست ندارند.

## انتشار

Migration لازم نیست. ابتدا فایل‌های جدید زیر را بارگذاری کنید:

- `core/view/PageSourceTrace.php`
- `assets/theme/page-source-trace.js`

سپس فایل‌های مصرف‌کننده را اعمال کنید:

- `core/view/View.php`
- `core/http/JsonResponse.php`
- `core/http/response.php`
- `assets/theme/help-center.js`

برای autoload authoritative، پیش از اعمال مصرف‌کننده‌ها `composer dump-autoload --no-scripts --no-interaction` را اجرا کنید، یا فایل‌های سازگار `vendor/composer/autoload_classmap.php` و `vendor/composer/autoload_static.php` همین انتشار را منتقل کنید. نام و حروف مسیر کلاس باید حفظ شوند. نسخهٔ asset با filemtime تازه می‌شود. برای بازگشت، ابتدا فایل‌های مصرف‌کننده را به نسخهٔ قبل برگردانید؛ سپس حذف فایل‌های جدید اختیاری است. داده و تنظیمات دیتابیس تغییری ندارند.

## بررسی

آزمون‌های محلی `php scripts/page_source_trace_test.php` و `node scripts/page_source_trace_browser_test.cjs` به مجموعهٔ انتشار افزوده شده‌اند؛ fixtureها به دیتابیس اصلی متصل نمی‌شوند. بعد از انتشار، راهنمای یک صفحهٔ عمومی و دو بخش پنل را با حساب شمارهٔ ۱ باز کنید و قالب اختصاصی، layout، جدول مشترک و فایل‌های دادهٔ بارگذاری‌شده را بررسی کنید. حالت تاریک، موبایل و Esc را نیز بررسی کنید. با مهمان، مدیر شمارهٔ دیگر و کاربر عادی، HTML نباید `pageSourceManifest` داشته باشد و API حتی با هدر opt-in نباید `_pageSources` برگرداند.
