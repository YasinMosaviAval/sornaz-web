# لینک دعوت در حساب کاربری اپلیکیشن

فایل قابل استقرار: `Modules/Analytics/Services/MobilePanelCatalog.php`.
کلاس، مسیر اصلی وب، جدول یا migration تازه‌ای اضافه نشده است.

عملیات مخفی `GET /api/sornaz/v1/panel/account/invite` از همان واسط Bearer پنل
به مسیر موجود `/system/my-invite` هدایت می‌شود. سرویس موجود شناسه را از
کاربر احراز هویت‌شده می‌گیرد؛ شناسهٔ کاربر از اپ پذیرفته نمی‌شود. این مسیر
همان اطلاعات لینک، کد و تعداد کاربران دعوت‌شدهٔ وب را برمی‌گرداند.

ابتدا فایل کاتالوگ وب را با حفظ سایر تغییرات نسخه مستقر کنید؛ سپس تغییرات
Flutter حساب کاربری را منتقل کنید. تغییر پایگاه داده لازم نیست. سرویس فعلی
دعوت و جدول‌های مورد استفادهٔ وب باید مثل نسخهٔ فعال سایت موجود باشند.
پوش GitHub به‌معنای استقرار این فایل در هاست نیست.

آزمون پس از استقرار: با حساب آزمایشی وارد اپ شوید و لینک/کد را با وب تطبیق
دهید؛ با توکن نامعتبر، درخواست باید رد شود. تغییر حساب نباید پاسخ حساب قبلی
را نمایش دهد. آزمون فایل `scripts/mobile_panel_test.php --api-only` قرارداد
کاتالوگ و جداسازی Bearer را با fixture بررسی می‌کند، نه اطلاعات حساب واقعی.

برای بازگشت، فایل کاتالوگ نسخهٔ قبلی و نسخهٔ سازگار اپ را برگردانید؛ داده‌ای
حذف یا مهاجرت نمی‌شود. هنگام انتقال انتخابی، AGENTS.md را منتقل نکنید.
