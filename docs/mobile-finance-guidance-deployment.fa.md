# هماهنگی امور مالی، تب‌ها و توضیحات پنل موبایل

فایل‌های اجرایی این تغییر: `Modules/Analytics/Controllers/Api/MobilePanelController.php`، `Modules/Analytics/Services/MobilePanelCatalog.php`، `Modules/Analytics/Services/MobilePanelNavigation.php` و `Modules/Analytics/Resources/mobile-panel-presentation.php`.

اصلاح تکمیلی به این فایل‌های اجرایی نیز نیاز دارد: `Modules/Academy/Controllers/Web/AcademyTermController.php`، `Modules/Analytics/Services/SitePageContentService.php`، منبع جدید `Modules/Analytics/Resources/panel-page-guidance.php` و قالب‌های `lessons.php`، `teachers.php`، `member-schedules.php`، `terms.php`، `pages.php` و `panel-page-guide.php` در پوشهٔ `Modules/Analytics/Resources/Views/sections/`.

علت نقص قبلی: توضیحات اولیه داخل قالب وب بودند و endpoint فقط موارد ذخیره‌شده در دیتابیس را برمی‌گرداند. منبع مشترک جدید، همان متن‌های قالب را بدون تغییر به وب و API می‌دهد و ترجمه‌های ذخیره‌شده جایگزین آن می‌شوند. نبود موقت فایل منبع در انتشار مرحله‌ای باعث خطای ۵۰۰ نمی‌شود؛ بااین‌حال فایل منبع باید اولین فایل آپلودشده باشد. پاسخ مالی برای هدر اختیاری `X-Sornaz-Panel-Features: 3`، دوره‌های اشتراک و پلن‌ها را نیز از سرویس اصلی اشتراک برمی‌گرداند. پاسخ درخواست‌های قدیمی تغییر نمی‌کند و خطای اشتراک، فاکتورهای موجود را پنهان نمی‌کند.

صرف تغییر فایل‌های مخزن محلی، API فعال روی هاست یا اپ نصب‌شده را تغییر نمی‌دهد. برای مشاهدهٔ همهٔ موارد در اپ نصب‌شده، ابتدا این فایل‌های وب روی سرور تست/اصلی طبق مجوز انتشار و سپس نسخهٔ تازهٔ اپ منتشر شوند. کلید کش پنل در کلاینت به نسخهٔ ۳ تغییر کرده تا کاتالوگ ذخیره‌شدهٔ نسخهٔ قبلی مانع نمایش قابلیت‌ها نشود. API قدیمی به‌جای پنهان‌کردن بی‌توضیح قابلیت‌ها، پیام نیاز به به‌روزرسانی دریافت می‌کند؛ متن‌های پیش‌فرض مشترک در قرارداد همراه اپ نیز موجودند.

کاتالوگ API عملیات موجود اشتراک و تخفیف را به کلاینت ارائه می‌دهد. خواندن و ذخیره توضیحات از همان `SitePageContentService` و ترجمه‌های دیتابیس وب انجام می‌شود؛ فقط کاربر ۱ مجاز به ذخیره است. تمام مسیرها احراز هویت و middleware موجود وب را حفظ می‌کنند. کلاس، وابستگی یا migration تازه‌ای در این تغییر ایجاد نشده است. تب‌های زمان‌بندی/تعطیلات/مرخصی به سرویس‌های موجود نسخه `1340a49` وابسته‌اند. تخفیف سازمانی همچنان نیازمند migration قبلی `2026_10_16_discount_organizations.sql` است؛ اجرای آن جزو این کار نیست.

ابتدا نسخهٔ قبلی وب و migrationهای لازم آن را روی محیط تست آماده کنید. فایل presentation و catalog/navigation را پیش از Controller به‌روز کنید و پس از بررسی API، اپلیکیشن جدید را منتشر کنید. کلاینت‌های قبلی همچنان مسیرهای قبلی را دارند؛ دادهٔ فاکتور، پرداخت و قیمت اشتراک تغییر نکرده است. برای بازگشت، ابتدا Controller و سپس سایر فایل‌ها را به نسخهٔ قبلی برگردانید؛ برگشت دیتابیس برای این تغییر لازم نیست. در حالت وب قدیمی، قابلیت‌های تازه تا به‌روزرسانی API در دسترس نخواهند بود.

آزمون کوتاه روی سرور تست: با حساب آموزشگاه و شعبه، فیلتر همه/آموزشگاه/شعبه، فاکتورهای موجود و دوره‌های واقعی اشتراک را بررسی کنید. جمع مالی باید پس از فیلتر با وب برابر باشد؛ ماه رایگان از دیتابیس می‌آید و ساختهٔ کلاینت نیست. دیالوگ پلن باید قیمت‌های سرویس را نمایش دهد؛ پرداخت آزمایشی فقط با تنظیمات تست انجام شود. یک تخفیف، تعطیلی و مرخصی آزمایشی ثبت و محدودهٔ سازمان و عضو کنترل شود. توضیح دوزبانه را با کاربر ۱ ذخیره و با کاربر عادی بخوانید؛ ذخیره با توکن کاربر عادی باید ۴۰۳ شود. API بدون توکن نیز باید رد شود.

آزمون‌های قرارداد/fixture جای تأیید روی دستگاه، MySQL، درگاه یا سرور اصلی نیستند. این تغییر در محیط اصلی منتشر نشده و migration اجرا نشده است.
