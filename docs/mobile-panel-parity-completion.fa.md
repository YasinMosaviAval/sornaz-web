# تکمیل تطبیق پنل وب و اپلیکیشن

بررسی قرارداد ۶۴ بخش پنل، مسیرهای عملیاتی و رابط‌های اختصاصی اپ انجام شد. کتابخانهٔ فایل‌های Markdown مدیر و گالری نمونه‌نمودارها کمبودهای اصلی بودند. قرارداد جدول‌های امور مالی و نوشته‌ها نیز همگام شد. حساب، تنظیمات و آزمون‌ها مقصد بومی جداگانه دارند؛ نبودن آن‌ها در منوی عمومی پنل به معنی فقدان قابلیت نیست. به‌روزرسانی زندهٔ اپ از polling فعلی استفاده می‌کند. این بررسی جای آزمون همهٔ نقش‌ها با دادهٔ واقعی را نمی‌گیرد.

## API و دسترسی

کلاینت با `X-Sornaz-Panel-Features: 5` قابلیت `guides.documentLibrary` دریافت می‌کند. بخش مخفی `guide-documents` چهار عملیات list/read/update/delete را از درگاه موجود موبایل اجرا می‌کند. API فهرست وب `GET /analytics/admin-guide-documents/list` است؛ مسیرهای خواندن/ویرایش/حذف قبلی دوباره استفاده می‌شوند. فهرست فقط metadata دارد و متن هنگام انتخاب دریافت می‌شود. هر دو لایهٔ کنترلر و سرویس فقط مدیر اصلی با شناسهٔ ۱ را مجاز می‌دانند. محدودیت مسیر، UTF-8، اندازه، قفل و نسخهٔ SHA256 سرویس فعلی حفظ شده‌اند؛ ویرایش یا حذف نسخهٔ قدیمی پاسخ 409 می‌دهد. کلاینت متن خصوصی را در cache پایدار یا fallback آفلاین ذخیره نمی‌کند و با تغییر حساب نمایشگر/ویرایشگر بسته می‌شود.

گالری شامل ۱۹ نوع نمونهٔ ثابت وب، حالت ساده/پیشرفته، جست‌وجو و فیلتر، تعامل و خروجی PNG بومی است؛ گزارش زنده نیست. شرط فعلی نمایش گالری در محیط توسعهٔ وب تغییر نکرده است. API جدیدی برای دادهٔ ثابت ساخته نشده است.

## فایل‌های این تغییر برای سرور

- `Modules/Analytics/Controllers/Api/MobilePanelController.php`
- `Modules/Analytics/Controllers/Web/AdminGuideController.php`
- `Modules/Analytics/Controllers/Web/AdminGuideDocumentController.php`
- `Modules/Analytics/Services/MobilePanelCatalog.php`
- `Modules/Analytics/Routes/routes.php`

کلاس PHP یا migration تازه لازم نیست. سرویس‌های موجود `AdminGuideService` و `AdminGuideDocumentService` و autoload سازگار همان نسخه باید حاضر باشند. اسکریپت‌های آزمون و این سند جزو فایل‌های اجرایی الزامی نیستند؛ حذف مستندات قابل مشاهدهٔ مدیر از سرور تصمیم جداگانه است.

## انتشار و بازگشت

ابتدا کنترلرهای وب (شامل متد index کتابخانه)، سپس routes، سپس catalog و در پایان کنترلر موبایل بارگذاری شوند؛ اپ جدید پس از وب منتشر شود. فعال‌سازی metadata فقط با header نسخهٔ ۵ است؛ کلاینت‌های نسخهٔ ۴ قرارداد قبلی را می‌بینند. اپ جدید با پاسخ قدیمی سرور، سه راهنمای قبلی را بدون درخواست کتابخانه نمایش می‌دهد. قرارداد مقصد گالری برای اپ قدیمی حفظ شده است. انتشار روی سرور اصلی یا اجرای migration انجام نشده است.

برای بازگشت، فایل‌های بالا را با نسخهٔ سازگار قبلی جایگزین کنید و ابتدا فعال‌سازی قابلیت را از کنترلر موبایل برگردانید؛ داده و فایل‌های ویرایش‌شدهٔ مدیر را بازنشانی نکنید. پس از آپلود، با مدیر اصلی فهرست و خواندن یک فایل، ذخیرهٔ فایل آزمایشی و تداخل نسخه را بررسی کنید؛ کاربر دیگر باید در فهرست/خواندن/نوشتن 403 بگیرد. آزمون نوشتنی فقط روی فایل ساختگی محیط تست انجام شود.

## اعتبارسنجی

آزمون قرارداد ۶۵ بخش (با transport مخفی)، bearer API با فایل واقعیِ موقت، رد مسیر و نقش غیرمجاز، حفظ session، تداخل ذخیره/حذف و پاک‌سازی fixture اجرا شد. آزمون مرورگر کتابخانهٔ وب نیز کنترل CSRF، نسخه و رندر را بررسی می‌کند. نتایج نهایی و محدودیت‌های مجموعهٔ انتشار در گزارش تحویل ذکر می‌شوند. هیچ درگاه، پیامک، دادهٔ اصلی یا دستگاه فیزیکی در این بررسی آزمایش نشده است.

نتیجهٔ مجموعهٔ انتشار وب: ۱۴۱ از ۱۴۳ گروه موفق بودند. اجرای اولیه پس از ۹۶ گروه کامل قطع شد و ۴۷ گروه پایانی با همان runner و fixtureها ادامه یافتند؛ همهٔ ۴۷ گروه ادامه موفق بودند. دو شکست، نبودن `scripts/music-practice-integration-test.php` و شکست `music_practice_browser_test.cjs` وابسته به همان فایل‌اند. این فایل پیش از تغییر حاضر نیز موجود نبود. lint فایل‌های PHP و `git diff --check` موفق بودند. بررسی `php-maintainability.php check` به دلیل بدهی اندازهٔ متدهای موجود پروژه موفق نشد؛ baseline تغییر داده نشده است. این نتیجه تأیید انتشار کامل سایت محسوب نمی‌شود.
