# درخواست اصلاح حفاظت فایل‌ها در هاست sornaz.com

## وضعیت تأییدشده

یک فایل واقعی زیر `/storage/chat/` بدون ورود با پاسخ `200` و هدر
`Cache-Control: max-age=1209600` از Nginx دریافت‌پذیر است. برنامه برای پیوست گفتگو
مسیر دانلود دارای کنترل عضویت دارد، اما تحویل مستقیم فایل ثابت آن را دور می‌زند.

## اقدام فوری پشتیبانی هاست

1. قواعد `nginx-private-files-emergency.conf` را در تنظیمات اختصاصی هر دو دامنه
   `sornaz.com` و `www.sornaz.com` روی HTTP و HTTPS اعمال و با locationهای موجود ادغام کنید.
   این فایل داخل `.htaccess` یا `public_html` اجرا نمی‌شود.
2. ابتدا `nginx -t` اجرا شود؛ فقط در صورت موفقیت، reload انجام شود.
3. کش پراکسی/CDN مربوط به مسیرهای خصوصی پاک شود. تنظیم `no-store` به‌تنهایی
   نسخه‌ای را که از قبل کش شده حذف نمی‌کند.
4. تنظیمات باید در محل سفارشی پایدار پنل ثبت شوند تا بازسازی تنظیمات دامنه آن‌ها را حذف نکند.

این اقدام فوری، دسترسی مستقیم به پیوست گفتگو و پوشه‌های خصوصی مشخص‌شده را می‌بندد؛
حفاظت دو پوشه ترکیبی زیر نیز برای تکمیل کار الزامی است.

## رسانه‌های عمومی و خصوصی در پوشه مشترک

این دو پیشوند نباید توسط location عمومی فایل‌های ثابت تحویل داده شوند:

- `/storage/account-media/`
- `/assets/media/library/`

درخواست این مسیرها باید با حفظ URI اصلی و query string به برنامه برسد؛ برنامه
عمومی‌بودن، حذف‌نشدن و مجوز فایل را بررسی می‌کند. `HEAD` و `Range` نیز باید حفظ شوند.
کش عمومی این مسیرها خاموش شود و پاسخ `Cache-Control: private, no-store` برنامه
نادیده گرفته نشود.

- اگر Nginx مستقیماً با PHP-FPM کار می‌کند، از تنظیمات ورودی `index.php` همین سایت
  استفاده کنید؛ `REQUEST_URI` باید URI اصلی درخواست بماند.
- اگر Nginx جلوی Apache است، پیشوندهای بالا با `location ^~` و **همان upstream و
  هدرهای مسیر پویای فعلی سایت** به Apache فرستاده شوند؛ URI نباید به `/index.php`
  تغییر کند. Apache و برنامه مسیریابی را انجام می‌دهند. شماره پورت backend را حدس نزنید.
- صرفاً افزودن regex بعد از location پسوندهای تصاویر کافی نیست. locationهای دقیق،
  aliasها و پیشوندهای خاص‌تر نیز باید بررسی شوند.
- CSS، JavaScript، تصاویر عمومی دیگر و مسیر ACME برای تمدید SSL باید فعال بمانند.

## معیار تحویل

1. آدرس مستقیم یک پیوست واقعی موجود، بدون کوکی، پاسخ `403` یا `404` بدهد؛ حتی با
   query string متفاوت یا درخواست Range نباید `200` یا `206` برگردد.
2. همان پیوست از مسیر `/analytics/chat/messages/{id}/file` برای عضو گفتگو باز شود
   و برای مهمان یا غیرعضو باز نشود.
3. آدرس مستقیم یک مدرک خصوصی واقعی مسدود باشد؛ دانلود مجاز صاحب حساب کار کند.
4. عکس عمومی پروفایل و ویدیوی گالری همچنان باز شوند و جابه‌جایی داخل ویدیو کار کند.
5. رسانه کتابخانه بعد از خصوصی‌شدن برای مهمان مسدود شود.
6. صفحه اصلی و فایل‌های CSS/JS همچنان پاسخ موفق بدهند.

## اجرای بررسی خواندنی

```text
node scripts/verify-private-files.cjs https://sornaz.com /storage/chat/ACTUAL-EXISTING-FILE
```

آدرس باید مربوط به فایلی باشد که واقعاً روی سرور وجود دارد. این ابزار فقط HEAD
می‌فرستد، محتوای فایل را دانلود نمی‌کند و موفقیت آن جای آزمون دانلود با حساب مجاز
و آزمون مدارک خصوصی را نمی‌گیرد. برای هر hostname و مسیر خصوصی واقعی تکرار شود.

مرجع رفتار location و تقدم پیشوندها:
https://nginx.org/en/docs/http/ngx_http_core_module.html#location

مرجع حفظ URI در پراکسی:
https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_pass
