# همگام‌سازی API و پنل موبایل — ۲۰۲۶/۱۰/۲۴

## دامنه و نتیجه

کاتالوگ ۶۳ بخش پنل با مسیرهای واقعی وب تطبیق داده شد. آزمون `scripts/mobile_panel_parity_test.php` مسیرهای عملیاتی را کنترل می‌کند؛ مسیرهای HTML، فرم، حمل‌ونقل realtime و جایگزین‌های امن موبایل در استثناهای صریح همین آزمون مستندند. این بررسی به معنی آزمون دستی تک‌تک نقش‌ها روی سرور اصلی نیست.

تغییرات مشترک در `sornaz-app` و `sornaz-app-release` اعمال شده‌اند. محدودیت‌های عمدی نسخهٔ گوگل‌پلی برای قابلیت‌های آزمایشی و OMR حفظ شده‌اند. فایل AAB قبلی شامل این تغییرات نیست.

| قابلیت | قرارداد و رفتار |
| --- | --- |
| تعیین وضعیت ترم | `POST /api/sornaz/v1/panel/terms/set-status` با شناسهٔ مسیر و مقادیر `status` و `fromStatus` طبق قرارداد موجود `payload_b64`؛ واگذاری به کنترلر و سرویس واقعی وب، حفظ مجوز و محدوده، رد وضعیت قدیمی با 409 و بارگیری مجدد در موبایل |
| نقشهٔ حرارتی تقویم | `GET /api/sornaz/v1/panel/schedules/heatmap`؛ همان فیلترها و محدودهٔ کاربر، اجبار داخلی `summary=heatmap` و محاسبه پیش از صفحه‌بندی؛ نمای هفتگی از دادهٔ کامل همان نمای مجاز استفاده می‌کند و درخواست اضافی ندارد |
| امتیاز شخصی | نمودار موجودی عمومی، حرفه‌ای و تخصصی از پاسخ واقعی API؛ موجودی تخصصی خالی برابر صفر، بدون تغییر قوانین امتیازدهی |
| قراردادها | نمودار دایره‌ای و حلقه‌ای اشخاص یکتا به تفکیک نوع قرارداد واقعی و فیلتر فعال |
| هنرجویان و ترم‌ها | نمودار درس و شیوهٔ برگزاری با حذف تکرار مناسب؛ شیوهٔ جلسات مقدم بر اطلاعات قدیمی کلاس است |
| نقشهٔ حرارتی و خروجی | نمایش همهٔ نتایج مجاز، تنظیم دامنهٔ رنگ، ذخیرهٔ PNG واقعی؛ در خطای دریافت خلاصه، جدول صفحهٔ جاری جایگزین آمار کامل نمی‌شود |
| فضای کار کاربران | نقش‌ها و مجوزها در کنار کاربران فقط برای نقش مجاز؛ قرارداد فیلترها از قالب‌های فعلی وب بازتولید شده است |

API تکراری برای اطلاعاتی که همین حالا از مسیرهای فهرست ارائه می‌شوند ساخته نشده است. احراز هویت bearer، middlewareهای دسترسی و سرویس‌های تراکنشی موجود حفظ شده‌اند. وابستگی جدید و کلاس PHP جدید اضافه نشده است.

## فایل‌های وب و ترتیب انتشار

این تغییر به تغییرات جاری پنل وب وابسته است؛ کاتالوگ جدید را به‌تنهایی روی نسخهٔ قدیمی سرور قرار ندهید.

۱. پیش از فعال‌کردن وضعیت‌های لغوشده/تعلیق‌شده، وضعیت اعمال migration موجود `docs/database/migrations/2026_10_23_term_cancellation_suspension.sql` بررسی شود. در صورت نیاز، پس از پشتیبان‌گیری و بازبینی روی محیط تست اجرا شود. این کار در این مرحله اجرا نشده است. سرویس روی ENUM قدیمی خطای قابل‌کنترل 409 می‌دهد و در درخواست عادی schema را تغییر نمی‌دهد.

۲. سرویس‌ها و کنترلرهای وابستهٔ تغییرات جاری وب ابتدا منتشر شوند: `Modules/Academy/Services/AcademyClassScheduleService.php`، `Modules/Academy/Services/AcademyTermService.php`، `Modules/Academy/Services/StudentAcademicDetails.php` و کنترلرهای متناظر نسخهٔ جاری که در راهنمای انتشار پنل آمده‌اند. سرویس نقشهٔ حرارتی باید خلاصه را پیش از صفحه‌بندی و پس از کنترل دسترسی بسازد. متد تعیین وضعیت ترم باید موجود باشد.

۳. فایل‌های API این تغییر، با حفظ نسخهٔ سازگار مجموعه، بارگذاری شوند:

- `Modules/Analytics/Controllers/Api/MobilePanelController.php`
- `Modules/Analytics/Services/UserPointService.php`
- `Modules/Analytics/Services/MobilePanelNavigation.php` (تغییرات جاری فضای کار)
- `Modules/Analytics/Resources/mobile-panel-filters.php`
- `Modules/Analytics/Resources/mobile-panel-presentation.php`
- `Modules/Analytics/Services/MobilePanelCatalog.php` (پس از وابستگی‌ها)

برای سایر فایل‌های رابط وب تغییرات جاری، راهنمای `docs/panel-workspaces-deployment.fa.md` و راهنمای انتشار نمودارها ملاک است؛ این فهرست مجوز حذف یا جایگزینی انتخابی سایر تغییرات جاری نیست. اسکریپت‌های آزمون/تولید فقط ابزار توسعه‌اند و مسیر عمومی اجرایی نیستند. تنظیمات، کلیدها، vendor سازگار و داده‌های سرور حفظ شوند. autoload جدید لازم نیست.

۴. با حساب آزمایشی مدیر و مدرس، فیلتر شاخه/روز و خلاصهٔ کامل تقویم، نمودارها و تغییر مجاز وضعیت ترم بررسی شوند. درخواست کاربر دیگر/آموزشگاه دیگر باید رد شود؛ درخواست با وضعیت قدیمی باید 409 بدهد. سپس اپ جدید برای هر دو شاخه ساخته و با همین سرور آزموده شود.

## بازگشت

نسخهٔ پشتیبان همان مجموعهٔ فایل‌های PHP و کاتالوگ/منابع بازگردانده شود؛ اپ نبود action جدید را تحمل می‌کند و برای وضعیت از قرارداد قبلی استفاده می‌کند. ENUM پایگاه داده کوچک نشود و دادهٔ وضعیت‌های ثبت‌شده حذف یا بازنویسی نشود. بازگشت فایل‌ها جای بررسی سازگاری داده را نمی‌گیرد.

## آزمون و محدودیت

۲۰۳ آزمون مرتبط Flutter در توسعه و ۱۹۲ آزمون در انتشار موفق شدند؛ آزمون‌های تازه شامل شمارش‌ها، فیلترها، دریافت تمام صفحات، وضعیت قدیمی، خطا و رقابت پاسخ‌ها و بایت‌های PNG هستند. آزمون تطابق API، جداسازی bearer/نقش، PHP lint، کنترل دسترسی آموزشگاه و نقشهٔ حرارتی مرورگر اجرا شدند. بررسی نگهداری کل مخزن بدهی‌های قبلی دارد؛ baseline افزایش داده نشده است.

انتشار سرور، migration اصلی، آزمون نوشتنی با حساب واقعی، ارسال پیامک/ایمیل، درگاه و ساخت/نصب APK یا AAB در این کار انجام نشده‌اند. اعتبارسنجی fixture جای آزمون یکپارچهٔ MySQL واقعی را نمی‌گیرد.

آزمون کامل وب با `node scripts/run-release-tests.cjs --browser` اجرا شد: ۱۰۷ از ۱۰۸ مجموعه در اجرای نخست موفق بودند. fixture قدیمی `term_batch_browser_test.cjs` برای فرم چهارمرحله‌ای و الزام ثبت هنرجو پیش از تعیین کلاس اصلاح و جداگانه با موفقیت اجرا شد؛ کد محصول برای عبور از آزمون تغییر نکرد. تحلیل ایستای فایل‌های مرتبط هر دو اپ بدون خطا یا هشدار است (نکات سبک کدنویسی موجود باقی‌اند).
