# دستگاه‌ها و علائم موسیقی ایرانی

۱۲ گزینهٔ دستگاه/آواز در ترتیب تعیین‌شدهٔ کاربر اضافه شدند. پس از دریافت فواصل و تصاویر مرجع، سرکلیدها با ۲۴ نت مبنا پیاده شدند. `scale_type` شناسهٔ `iran_*` است و `key` نت مبنا را نگه می‌دارد: مانند `G`، `Db`، `A:k` یا `C:o`. توکن `:k` کرن و `:o` سری است. شناسه‌ها و ترتیب کامل در `IRANIAN_KEYS` سرویس PHP و `iranianTonics` مدل JavaScript یکسان‌اند. نام نمایشی فارسی/انگلیسی فقط در رابط ساخته می‌شود.

فواصل دقیق کاربر به واحد ربع پردهٔ صحیح ذخیره شده‌اند و علائم هفت درجه با املای دیاتونیک محاسبه می‌شوند. ترتیب هر گروه علامت همان ترتیب متداول دیز/سری (فا، دو، سل، ر، لا، می، سی) و بمل/کرن (سی، می، لا، ر، سل، دو، فا) است؛ در سرکلیدهای ترکیبی ابتدا گروه بالابرنده و سپس پایین‌آورنده می‌آید، مطابق نمونهٔ تصویری. علائم بعد از کلید و پیش از میزان‌نما در آغاز هر خط، روی حامل سل، فا و کلیدهای دو رسم می‌شوند. پخش، تغییر سرکلید در میزان و نمایش نت‌های پیانو از همین محاسبه استفاده می‌کنند. این فواصل برای سرکلیدند؛ قواعد ملودیک یا مدگردی موسیقی ایرانی به قواعد گام غربی تبدیل نشده‌اند.

علائم جدید برای نت، نت آکورد و نت زینت در API موجود پذیرفته می‌شوند:

| مقدار فنی | عنوان | تغییر نسبت به نت طبیعی |
| --- | --- | --- |
| `k` | کُرُن | نیم نیم‌پرده پایین‌تر / ربع پرده |
| `o` | سُری | نیم نیم‌پرده بالاتر / ربع پرده |
| `bk` | بمل کُرُن | ۱٫۵ نیم‌پرده پایین‌تر / سه‌ربع پرده |
| `#o` | دیز سُری | ۱٫۵ نیم‌پرده بالاتر / سه‌ربع پرده |

نشانه‌های ایرانی از glyphهای `accidentalKoron` و `accidentalSori` موجود در VexFlow همراه پروژه رسم می‌شوند؛ علائم ترکیبی از دو جزء تشکیل می‌شوند. پخش از تبدیل عددی فرکانس موجود استفاده می‌کند؛ کوک ربع‌پردهٔ مساوی طبق مقادیر کاربر منظور است. مقدارهای قدیمی `d` و `+` حفظ شده‌اند. JSON نماد دقیق را نگه می‌دارد؛ MusicXML با alter کسری، سرکلید غیرسنتی `key-step/key-alter` و metadata دستگاه/مبنا صادر/وارد می‌شود. metadata فایل‌های خود اپ، دستگاه‌های دارای فواصل یکسان را هنگام بازخوانی از هم متمایز می‌کند. سرکلید ایرانی ناشناختهٔ فایل بیرونی بدون اطلاعات کافی، به دو ماژور تبدیل نمی‌شود و با خطای روشن رد می‌شود.

## انتشار

فایل‌های اجرایی این مرحله:

- `Modules/Notation/Services/NotationService.php`
- `assets/notation/model.js`
- `assets/notation/importer.js`
- `assets/notation/score_renderer.js`
- `assets/notation/ui_glyphs.js`
- `assets/notation/notation.js`

API تازه، کلاس PHP تازه، وابستگی یا migration لازم نیست؛ قرارداد endpoint و کنترل مالکیت فعلی حفظ شده است. ابتدا چهار فایل پشتیبان model/importer/renderer/glyphs و سرویس اعتبارسنجی را اعمال کنید و در پایان notation.js را که گزینه‌ها را فعال می‌کند بارگذاری کنید. پس از آن اپ جدید منتشر شود. ورودی وب فعلی نسخهٔ فایل‌های محلی را از filemtime می‌سازد؛ fallback نبودن فهرست دستگاه‌ها از شکست موقت حین اعمال مرحله‌ای جلوگیری می‌کند. فایل‌ها با نام و حروف همین مسیرها برای Linux منتقل شوند. انتشار اصلی انجام نشده است.

برای بازگشت، ابتدا گزینه‌های جدید را از رابط غیرفعال کنید. تا وقتی نت‌هایی با نمادهای جدید وجود دارند، پذیرش API و پشتیبانی خواندن/رندر آن‌ها را نگه دارید؛ برگشت کامل به نسخهٔ قدیمی می‌تواند ذخیره یا نمایش این نت‌ها را مختل کند. داده‌ها خودکار به علائم دیگر تبدیل یا پاک نشوند. نسخه‌های قدیمی اپ نیز برای ویرایش این علائم نیاز به به‌روزرسانی دارند.

پس از آپلود در محیط تست، با حساب آزمایشی یک نت چهارعلامتی ذخیره و دوباره باز کنید، پخش و خروجی/ورودی JSON را بررسی کنید و خواندن یا ویرایش همان نت از حساب دیگر را رد کنید. آزمون نوشتنی در محیط اصلی انجام نشده است.

## آزمون‌ها

`scripts/notation_validation_test.php` حفظ ۱۲ حالت × ۲۴ نت مبنا × چهار علامت در نت/آکورد/زینت و رد مبنای نامعتبر را بررسی می‌کند. آزمون مدل، ذخیرهٔ محلی وب، حساب وب، مرورگر parity و fixtureهای مشترک نت‌نویسی اجرا شدند. `tools/iranian_signature_check.cjs` اپ تمام ۲۸۸ ترکیب، هفت فاصله، پخش ضمنی و پنج مثال کاربر را می‌سنجد. fixture مرورگر همهٔ ترکیب‌ها را روی حامل سل/فا و نمونه‌ها را روی کلیدهای دیگر رسم می‌کند، عدم تداخل با کلید/میزان‌نما را می‌سنجد و نگهداری دستگاه، مبنای ربع‌پرده‌ای و تغییر سرکلید بین میزان‌ها در MusicXML را بررسی می‌کند. اسکریپت قدیمی `notation_browser_test.cjs` به selector منسوخ `data-value=q` برای واحد ضرب وابسته است و در همان نقطه timeout می‌شود؛ مجموعه‌های جاری parity و shared-features موفق بودند. آزمون فیزیکی دستگاه و سرور اصلی انجام نشده‌اند.

نتیجهٔ نهایی: مجموعهٔ انتشار وب ۱۴۱ از ۱۴۳ گروه موفق داشت؛ دو شکست همان نبودن `music-practice-integration-test.php` و آزمون مرورگر وابسته به آن است. پس از اصلاح نهایی جای‌گذاری سرکلید وسط خط حامل فا، ۱۶ اجرای اختصاصی مرورگر اپ دوباره موفق شدند. قرارداد ترتیب ۲۴ نت در PHP و JavaScript و خروجی همهٔ ۲۸۸ سرکلید در مدل وب و اپ با هم تطبیق داده شد. lint فایل‌های PHP/JavaScript و diff check موفق بودند. بررسی maintainability همچنان بدهی متدهای قدیمی پروژه، از جمله `NotationService::validate` را گزارش می‌کند؛ baseline تغییر نکرده است.
