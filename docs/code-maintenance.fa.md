# راهنمای نگهداری کد

[نسخهٔ انگلیسی](code-maintenance.md)

## نصب ابزارهای توسعه

از PHP نسخهٔ ۸٫۲ و Node.js همراه با npm استفاده کنید. دستورهای زیر را از پوشهٔ اصلی پروژه اجرا کنید:

```sh
php scripts/install-php-formatter.php
npm ci --prefix scripts/format-tools --ignore-scripts --no-audit --no-fund
```

نسخهٔ PHP CS Fixer روی `3.95.27` ثابت شده و پیش از نصب، صحت فایل آن با SHA-256 بررسی می‌شود. نسخهٔ Prettier نیز روی `3.9.9` ثابت شده و فایل قفل npm دارد. فایل‌های نصب‌شدهٔ این ابزارها از وابستگی‌های Composer محیط اصلی جدا هستند و Git آن‌ها را نادیده می‌گیرد. هنگام نصب، بررسی اعتبار گواهی TLS را فعال نگه دارید.

## بررسی‌های معمول

```sh
composer style:check
composer style:fix
composer quality:report
composer quality:check
composer test:release
```

کاربرد دستورها:

- `style:check`: بررسی رعایت قالب‌بندی کد.
- `style:fix`: اصلاح قالب‌بندی و بازنویسی فایل‌ها.
- `quality:report`: گزارش خطوط طولانی و متدهای بزرگ.
- `quality:check`: بررسی افزایش اندازهٔ متدها نسبت به خط مبنا.
- `test:release`: اجرای مجموعه آزمون‌های انتشار، شامل آزمون‌های مرورگر.

در صورت امکان، تغییرات قالب‌بندی را جدا از تغییرات رفتار برنامه بازبینی کنید.

قالب‌بندی PHP پوشه‌های `core` و `Modules` را پوشش می‌دهد؛ قالب‌های موجود در `Resources` و وابستگی‌های موجود در `Lib` مستثنا هستند. هنگام اضافه شدن ابزار، این محدوده شامل ۴۸۸ فایل بود. قالب‌بندی JavaScript فایل‌های `assets/**/*.js` را پوشش می‌دهد؛ فایل‌های vendor و اسکریپت‌های فشرده‌شده مستثنا هستند. این محدوده شامل ۱۱۴ فایل بود.

اصلاح‌گرهای پرخطر PHP غیرفعال هستند. برای دستورهای کنترل جریان، آکولادهای صریح اضافه می‌شود. قالب‌ها و اسکریپت‌های تعبیه‌شده در آن‌ها، پیش از گسترش دامنهٔ قالب‌بندی به بازبینی جداگانه نیاز دارند.

## اندازهٔ متدها

دستور `quality:report` خطوط طولانی و تابع‌ها یا متدهای نام‌داری را فهرست می‌کند که بدنهٔ آن‌ها بیش از ۴۰۰ توکن دارد. توکن‌ها اجزای نحوی کد هستند و در این شمارش، فاصله‌ها و توضیحات کد محاسبه نمی‌شوند. این معیار اندازهٔ کد را می‌سنجد، نه پیچیدگی حلقوی یا تعداد مسیرهای اجرای آن. تابع‌های بی‌نام جزئی از اندازهٔ متد دربرگیرندهٔ خود محسوب می‌شوند. رشته‌های طولانی SQL و فهرست‌های بزرگ داده همچنان به بازبینی انسانی نیاز دارند.

دستور `quality:check` برای متدهای بزرگ جدید یا افزایش اندازه نسبت به مقادیر ثبت‌شده در `scripts/php-complexity-baseline.json` خطا می‌دهد. این خط مبنا در زمان تهیهٔ راهنما، ۱۲۸ متد بزرگ موجود را ثبت کرده است. ثبت آن‌ها به معنای پذیرفتنی بودن اندازه‌شان نیست؛ بدهی فنی باقی‌مانده را مشخص می‌کند.

دستور زیر را فقط پس از بازبینی تغییرات اجرا کنید؛ خط مبنا را صرفاً برای رفع خطای بررسی دوباره تولید نکنید:

```sh
php scripts/php-maintainability.php baseline
```

این بررسی‌ها با اجرای دستور فعال می‌شوند و هنوز در فرایند یکپارچه‌سازی مداوم یا CI اجباری نشده‌اند.

پیش از تفکیک مسئولیت‌های سرویس‌های پرداخت، ثبت‌نام، مجوزها و پشتیبان‌گیری، آزمون‌های رفتاری آن‌ها را در اولویت قرار دهید. هرجا مفید است، اعتبارسنجی، بررسی دسترسی، خواندن داده، تغییر داده و آماده‌سازی خروجی را جدا کنید. محدودهٔ تراکنش‌ها، ترتیب بررسی دسترسی و نوع داده‌های پاسخ API را حفظ کنید. انتقال یک متد بزرگ به فایلی دیگر، بدون بهبود تقسیم مسئولیت‌ها، مشکل نگهداری را حل نمی‌کند.

## بازآرایی انجام‌شده در این مرحله

- در `ChatService::messages`، واکشی صفحهٔ پیام‌ها، واکشی پیام‌های به‌روزشده، ثبت آخرین پیام خوانده‌شده، بارگذاری واکنش‌ها و آماده‌سازی خروجی پیام‌ها جدا شدند. بررسی عضویت همچنان پیش از دسترسی به پیام‌ها انجام می‌شود.
- در `ContactMessageService::submit`، اعتبارسنجی، ایجاد پیام و ذخیرهٔ ترجمه‌ها جدا شدند. عملیات نوشتن همچنان داخل تراکنش قبلی انجام می‌شود.
- آزمون مرورگر فرم تماس اصلاح شد تا تغییر فاصله‌گذاری ناشی از قالب‌بندی باعث شکست آن نشود؛ بررسی‌های رفتاری آزمون حفظ شدند.

برای تغییری که صرفاً شامل فاصله‌گذاری است، می‌توانید پیش از قالب‌بندی از کد تصویری از توکن‌ها تهیه کنید و پس از آن مقایسه را اجرا کنید:

```sh
php scripts/php-maintainability.php snapshot
# تغییرات صرفاً مربوط به فاصله‌گذاری را اعمال کنید.
php scripts/php-maintainability.php verify
```

اضافه کردن آکولاد یا استخراج متدها عمداً توکن‌ها را تغییر می‌دهد. مقایسهٔ توکن‌ها اثبات‌کنندهٔ حفظ رفتار برنامه نیست و جای آزمون‌ها را نمی‌گیرد.

پیش از انتشار، آزمون‌های انتشار و بررسی صحت نحوی فایل‌ها را اجرا کنید. آزمون‌های مرورگر در محیط‌های جداشدهٔ JavaScript و آزمون‌های پایگاه داده با داده‌های آزمایشی جداشده اجرا می‌شوند؛ موفقیت آن‌ها تأییدکنندهٔ تنظیمات هاست اصلی یا رفتار واقعی درگاه پرداخت نیست.

این مرحلهٔ نگهداری به مهاجرت پایگاه داده یا ساخت APK نیاز ندارد. رسیدگی به ایرادهای امنیتی و منطق کسب‌وکار که قبلاً شناسایی شده‌اند، کار جداگانه‌ای است.
