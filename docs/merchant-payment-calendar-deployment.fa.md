# اصلاح دامنه آغاز پرداخت و نمایش تقویم سازمان‌ها

## علت و رفتار جدید

اپلیکیشن قبلاً نشانی StartPay زرین‌پال را مستقیم در مرورگر باز می‌کرد؛ این ورود صفحه‌ای از دامنه پذیرنده به‌عنوان Referer نداشت. راهنمای رسمی زرین‌پال، برای نرم‌افزارها استفاده از یک صفحه واسط روی دامنه رسمی را مقرر کرده است:
https://www.zarinpal.com/blog/الزام-تطابق-دامنه-در-فرآیند-پرداخت/

درخواست‌های جدید و بازیابی پرداخت در انتظارِ فاکتور و اشتراک اکنون نشانی `APP_URL/academy/payments/zarinpal/continue` را برمی‌گردانند. این صفحه با توکن تصادفی موجود، فقط authority ذخیره‌شده را می‌خواند و مرورگر را به میزبان ثابت زرین‌پال می‌برد؛ redirect هدف از ورودی کاربر پذیرفته نمی‌شود. GET واسط هیچ پرداخت یا تسویه‌ای ایجاد نمی‌کند. پرداخت انجام‌شده/توکن نامعتبر رد می‌شود. انتقال با سند HTML و کلیک مرورگر انجام می‌شود، نه redirect HTTP؛ حالت بدون JavaScript نیز دکمه ادامه دارد. `Referrer-Policy: origin` فقط دامنه را به درگاه می‌فرستد و توکن را در Referer افشا نمی‌کند. مسیرهای احراز هویتِ ایجاد پرداخت، قفل، مبلغ و callback تغییری نکرده‌اند.

در اپلیکیشن، کارت اشتراک از همان `PanelSectionCard` کارت توضیحات، رنگ تم و شعاع مشترک استفاده می‌کند و باز/بسته می‌شود. مقادیر null/خالی تلفن شعبه به خط تیره تبدیل شده‌اند. تب‌های بالای تقویم «همه»، «آموزشگاه» و شعبه‌های در دسترس هستند؛ انتخابگر سازمان از فیلترها حذف شده و دو کنترل نمایش داخل محتوای سازمان قرار دارند. عنوان‌ها در وب و اپلیکیشن «نمایش جدولی» و «نمایش برنامه هفتگی» شده و نمای هفتگی پیش‌فرض است. انتخاب آموزشگاه در API، دوره‌های دارای `branch_id IS NULL` را با حفظ محدوده مجاز برمی‌گرداند. بازه هفته‌ها نیز سازمان انتخابی و جلسات دارای کلاس را رعایت می‌کند.

## ترتیب استقرار و بازگشت

شاخه فعلی وب پیش از ویرایش با GitHub همگام شد؛ فایل‌های موقت قبلی حفظ شدند. فایل قالب و JavaScript واسط و مسیر GET جدید باید پیش از سرویس‌هایی که URL جدید برمی‌گردانند روی سرور حاضر باشند. سپس تغییر سرویس‌های پرداخت و تقویم/قالب/JS منتشر و کش JS/CDN تازه شود. اپلیکیشن جدید پس از API وب منتشر شود؛ اپلیکیشن قبلی نیز URL مطلق واسط را مصرف می‌کند. در استقرار با تعویض اتمی نسخه، همه فایل‌ها با هم جابه‌جا شوند.

`APP_URL` موجود باید همان دامنه رسمی ثبت‌شده برای پذیرنده زرین‌پال و محل callback باشد؛ این اصلاح مقدار تنظیمات واقعی را تغییر نداده و پنل پذیرنده قابل بررسی نبوده است. پس از استقرار، انتقال از اپلیکیشن و callback یک پرداخت آزمایشی مجاز و همین صفحات در دستگاه واقعی/تم‌های روشن و تاریک بررسی شوند. هیچ APK/خروجی اپلیکیشن یا انتشار روی هاست اصلی انجام نشده است.

برای rollback، سرویس‌های برگرداننده URL واسط را ابتدا به نسخه قبلی برگردانید و صفحه/مسیر/JS واسط را تا پایان عمر لینک‌های در انتظار حفظ کنید. رکورد پرداخت یا currency آن حذف/تبدیل نشود. بازگشت قالب/JS تقویم همراه با تازه‌کردن کش انجام شود.

تغییرات از OMR و تحلیل آزمایشی عملکرد مستقل‌اند و برای انتقال انتخابی به release آماده‌اند. AGENTS.md و فایل‌های پشتیبان/لاگ/خروجی ساخت منتقل نشوند.
