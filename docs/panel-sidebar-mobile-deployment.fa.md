# تطبیق منوی پنل موبایل با وب

## هماهنگی با ورک‌اسپیس فعلی

تغییرات GitHub تا کامیت `347dd0301b208f35609c369c479d03153df3b6de` با تغییرات وب ادغام شده‌اند. ترتیب تازهٔ کلاس‌ها و کارمندها و انتقال دوره‌ها به تب سوم درس‌ها حفظ شده است. به همین دلیل آزمون ترتیب منوی موبایل نیز با سایدبار فعلی هماهنگ شده و مقصدهای `course-levels` و `courses` در `links` آیتم مدیریتی درس‌ها ارسال می‌شوند. این مقصدها فقط از بخش‌های مجاز کاتالوگ انتخاب می‌شوند؛ منوی مستقل دوره‌ها دوباره اضافه نشده است. پروژهٔ Flutter تغییر نکرده است.

آزمون‌های ورودی بازنشستهٔ `scripts/user_access_partial_save_test.php` همراه آزمون‌های نقش کارمند در `scripts/staff_role_policy_test.cjs` موجودند و runner از ورودی جدید استفاده می‌کند. فایل‌های آزمون جزو بستهٔ اجرای سایت نیستند.

مرجع منو اکنون خود `Modules/Analytics/Resources/Views/sections/sidebar.php` است. API کاتالوگ عملیات را همچنان در `sections` نگه می‌دارد و منوی مستقلِ مجاز را با `navigationVersion: 1` و `navigation` برمی‌گرداند. وجود API یک عملیات، دلیل اضافه شدن آن به منوی موبایل نیست.

## قواعد حفظ‌شده

- ترتیب، عنوان‌ها، گروه‌ها، دسته‌های گالری و نمایش یا عدم نمایش آیتم‌ها از رندر همان Sidebar برای کاربر احراز هویت‌شده استخراج می‌شوند. HTML، اطلاعات سربرگ و نام کاربر به اپ ارسال نمی‌شوند.
- «سوابق و دستاوردها» و منوی نقش‌ها در Sidebar فعلی به بنیان‌گذار محدودند. درخواست فعلی مجوز گسترش آن‌ها به آموزشگاه نیست.
- گزارش‌ها و گالری نمودارها در منوی فعلی فقط برای مدیر سایت در محیط محلی هستند. گزارش‌های نمونهٔ `assets/Analytics/js/reports.js` دادهٔ عملیاتی نیستند. «گالری نمودارها» API داده ندارد؛ اپ آن را صریحاً به‌عنوان بخش نمایشی وب معرفی و لینک وب را ارائه می‌کند. این قسمت به‌عنوان پیاده‌سازی بومی کامل معرفی نمی‌شود.
- گزینه‌های شخصی به endpointهای مالکیت‌دار `my-gallery`، `my-lessons`، `my-schedule`، `my-finance` و `my-settings` وصل می‌شوند، اما عنوان «من» و آیتم اضافه وارد منوی وب‌مانند نمی‌شود. حساب آموزشگاه و شعبه به کاتالوگ مدیریتیِ مجاز خودش متصل می‌ماند.
- شناسهٔ ۱ از آیتم نت‌نویسی به ابزار موجود اپ می‌رود. API جدید هیچ مجوز نوشتن تازه‌ای ایجاد نمی‌کند و middleware و مرز آموزشگاهِ endpointهای موجود پابرجاست.
- مسیر جدید `lessons/{id}/usage` از آخرین تغییر گیت‌هاب در کاتالوگ موبایل نیز ثبت شده است.

## فایل‌های این تغییر برای استقرار

1. `Modules/Analytics/Services/MobilePanelNavigation.php` (کلاس جدید؛ ابتدا این فایل را آپلود کنید).
2. `Modules/Analytics/Resources/Views/sections/sidebar.php` (دو تگ کوتاه PHP به تگ استاندارد تبدیل شده‌اند تا خاموش بودن `short_open_tag` شرط دسترسی را بی‌اثر نکند).
3. `Modules/Analytics/Services/MobilePanelCatalog.php` (تغییر جدید: عملیات مشاهدهٔ محل استفادهٔ درس).
4. `Modules/Analytics/Controllers/Api/MobilePanelController.php` (پس از کلاس جدید، قرارداد منو را فعال کنید).

این فهرست فقط فایل‌های ناوبری موبایل را پوشش می‌دهد. برای انتشار کامل، فایل‌های سایر تغییرها، از جمله کاتالوگ عملیات، امنیت درس‌ها، PageSourceTrace و راهنماهای قابل ویرایش پنل را نیز مطابق مستندات همان نسخه منتقل کنید.

نیازی به migration یا پکیج جدید نیست. `ext-dom` از قبل وابستگی Composer است. autoload استاندارد PSR-4 برای کلاس جدید موجود است؛ اگر روی سرور Composer با classmap-authoritative اجرا می‌شود، classmap را در فرایند استقرار معمول به‌روز کنید. تنظیمات و داده‌های واقعی را تغییر ندهید.

ابتدا وب را مستقر کنید و سپس نسخهٔ اپ را منتقل کنید. اپ جدید در برابر API قدیمی، به‌جای منوی نادرست، پیام لزوم به‌روزرسانی API می‌دهد. سرور جدید با اپ قدیمی سازگار است؛ `sections` و مسیر عملیات قبلی حذف نشده‌اند.

## تست و بازگشت

```powershell
C:\xampp\php\php.exe scripts/panel_sidebar_navigation_test.php
C:\xampp\php\php.exe scripts/mobile_panel_test.php --api-only
C:\xampp\php\php.exe -d short_open_tag=1 scripts/mobile_panel_test.php
C:\xampp\php\php.exe scripts/mobile_panel_parity_test.php
C:\xampp\php\php.exe scripts/personal_panel_data_test.php
```

نسخهٔ کامل تست پنل، قالب قدیمی پیش‌نمایش وب را هم include می‌کند که هنوز تگ کوتاه PHP دارد؛ به همین دلیل فرمان کامل با `-d short_open_tag=1` اجرا می‌شود. این تنظیم فقط برای همان فرایند تست است و `php.ini` سرور یا سیستم را تغییر نمی‌دهد. runner نیز همین گزینه را فقط برای این تست اعمال می‌کند.

نتایج این مأموریت: آزمون Sidebar برای ۹ حالت نقش/مالکیت و محیط محلی موفق بود؛ آزمون کامل پنل با پرچم بالا و حالت API-only، تطابق ۶۰ گروه قرارداد عملیات، داده و API شخصی و ۱۴۱ بررسی مرز آموزشگاه موفق بودند. بررسی نگهداری PHP همچنان موارد قدیمیِ عبور از حد پیچیدگی را گزارش می‌کند؛ کلاس جدید ناوبری در آن‌ها نیست. آزمون‌های حساب واقعی و استقرار سرور انجام نشده‌اند.

پس از استقرار، با توکن آزمایشی هر نقش پاسخ `/api/sornaz/v1/panel` را بررسی کنید و منوی اپ را با ورود همان حساب به وب مقایسه کنید. توکن را در لاگ یا گزارش ذخیره نکنید. کاربر عادی نباید منوی نقش‌ها، آیتم‌های مدیریتی یا اطلاعات کاربر دیگر را ببیند. روی آموزشگاه و شعبه، ویرایش یک رکورد آزمایشی در محدودهٔ خود و رد دسترسی به رکورد آموزشگاه دیگر را بررسی کنید. این تست‌های زنده، در محیط فعلی انجام نشده‌اند.

برای بازگشت، نسخهٔ قبلی کنترلر و Catalog را همراه نسخهٔ قبلی اپ بازگردانید. کلاس جدید می‌تواند بدون استفاده روی سرور باقی بماند. برگشت فقط API، باعث نمایش پیام نیاز به API جدید در اپ جدید خواهد شد. تغییر پایگاه داده‌ای برای بازگشت وجود ندارد.
