# تفاوت فایل‌های پنل محلی و آنلاین — ۲۲ اکتبر ۲۰۲۶

فایل‌های عمومی `https://sornaz.com/assets/Analytics/js/` فقط‌خواندنی مقایسه شدند. سه فایل زیر با نسخهٔ مخزن متفاوت بودند و اصلاحات اخیر را نداشتند. دریافت با URL نسخه‌دار تازه و هدر درخواست `Cache-Control: no-cache` نیز همان محتوای قدیمی را برگرداند. مشکل مشاهده‌شده صرفاً کش مرورگر نیست؛ مسیر عمومی سایت این فایل‌های جدید را سرو نمی‌کند. بدون دسترسی میزبانی، تفاوت مسیر آپلود، نسخهٔ قدیمی روی میزبان و کش واسط را نمی‌توان قطعی تفکیک کرد.

| فایل | آغاز SHA-256 محلی | آغاز SHA-256 آنلاین |
| --- | --- | --- |
| `students.js` | `74430269aed24e3e` | `321da54c0286e4d1` |
| `student-templates.js` | `101827bfe9277153` | `f4e3e7beaff79f98` |
| `terms.js` | `6da3eb02eee06561` | `81ff31abb476ab94` |

پاسخ عمومی هر سه فایل `200 OK` و دارای `Cache-Control: max-age=1209600` (۱۴ روز) بود. کارکرد صحیح اپ با این نتیجه سازگار است: اپ از API و رابط Flutter استفاده می‌کند و این JavaScriptها را بارگذاری نمی‌کند.

## اصلاح و فایل‌های لازم

نسخه‌گذاری `pushScript` و `pushStyle` فقط از `filemtime` استفاده می‌کرد. آپلودی که زمان فایل را حفظ کند، می‌تواند محتوای تازه را با همان URL قبلی منتشر کند. نسخه اکنون از SHA-256 محتوا ساخته می‌شود؛ تغییر محتوا حتی با زمان و اندازهٔ ثابت، URL تازه می‌سازد. محتوای ثابت با تغییر صرف زمان، URL خود را حفظ می‌کند. رفتار آموزشی، API و Flutter در این اصلاحیه تغییر نکرده‌اند.

دو فایل اجرایی PHP تغییرکرده‌اند:

- `core/support/AssetManager.php`
- `core/support/helpers.php`

**تمام JavaScriptهای فعلی `assets/Analytics/js/` نیز باید در همین مسیر عمومی سایت فعال حاضر باشند.** انتقال این دو PHP به‌تنهایی محتوای قدیمی سرور را جدید نمی‌کند. فهرست دقیق ۸۹ فایل (دو PHP و ۸۷ JavaScript) با SHA-256 کامل در `docs/panel-assets-upload.sha256` آماده است. manifest شامل تنظیمات، رسانه، رمز یا دادهٔ کاربران نیست؛ `assets/vendor/` و رسانه‌ها جزو این انتقال نیستند.

مبنا پوشهٔ سایت فعال، کنار `index.php` فعال است. در ساختار فعلی مخزن، منبع فایل‌ها `assets/Analytics/js/` است؛ انتقال به نسخه‌ای دیگر در `Modules/Analytics/Resources/Assets/` یا `public/assets/` جایگزین انتقال به مسیر عمومی فعال نمی‌شود. نام مسیر فیزیکی میزبان بدون دسترسی سرور قابل تأیید نیست.

## انتشار و بازگشت

1. از دو PHP و JavaScriptهای فعال پشتیبان بگیرید؛ تنظیمات و رسانه‌های کاربران حفظ شوند.
2. ابتدا `AssetManager.php` منتقل شود؛ متد افزوده با helper قبلی سازگار است.
3. JavaScriptهای همین نسخه هماهنگ در `assets/Analytics/js/` سایت فعال قرار گیرند؛ پوشه‌های دیگر حذف نشوند.
4. سپس `helpers.php` منتقل شود. کش OPcache/HTML طبق روش میزبانی تازه شود؛ endpoint عمومی پاک‌سازی کش ایجاد نشده است.
5. کش CDN/میزبانی فایل‌های قدیمی پس از انتقال تازه شود. محتوای عمومی با URL تازه باید با manifest برابر باشد؛ پیام موفقیت آپلود به‌تنهایی کافی نیست.
6. پنل یک‌بار دوباره باز شود. درخواست فایل‌ها در Network باید نسخهٔ محتوایی تازه داشته باشد؛ افزودن هنرجو فقط ترم باز را نشان دهد و ترم گروهی تا تکمیل هر دو ظرفیت باز بماند.

در صورت دسترسی SSH، از پوشهٔ فعال سایت:

```sh
sha256sum -c docs/panel-assets-upload.sha256
```

این دستور فقط می‌خواند. در بازگشت، ابتدا helper قبلی و سپس AssetManager قبلی بازگردند تا helper تازه به متد حذف‌شده ارجاع ندهد. JavaScriptها با نسخهٔ سازگار همان انتشار بازگردند. migration یا تغییر داده لازم نیست.

## آزمون

`php scripts/asset_version_test.php` با helperهای واقعی، جایگزینی محتوای هم‌اندازه و زمان ثابت را بازتولید کرد: پیش از اصلاح شکست خورد و پس از اصلاح موفق شد. JS/CSS، پایداری URL محتوای ثابت و مسیر عمومی بررسی شدند. بررسی نحوی PHP، `git diff --check` و مجموعهٔ انتشار وب نیز اجرا می‌شوند. فایل‌های موقت آزمون پاک می‌شوند. هیچ فایل یا داده‌ای در سرور اصلی تغییر نکرده است.
