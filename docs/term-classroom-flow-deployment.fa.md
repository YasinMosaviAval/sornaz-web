# تعیین کلاس پس از ثبت هنرجو

فایل‌های این تغییر برای سرور:

- `Modules/Academy/Services/AcademyClassScheduleService.php`
- `Modules/Academy/Services/AcademyTermService.php`
- `Modules/Academy/Services/TermEnrollmentCapacity.php`
- `Modules/Analytics/Services/AdminDashboardService.php`
- `assets/Analytics/js/dashboard-templates.js`
- `assets/Analytics/js/students.js`
- `assets/Analytics/js/term-templates.js`
- `assets/Analytics/js/terms.js`

فایل تست جدید `scripts/term_classroom_flow_test.cjs` برای توسعه است و برای اجرای سرور لازم نیست. کلاس جدید یا migration نداریم. دادهٔ واقعی تغییر نکرده است.

ابتدا فایل‌های PHP و سپس فایل‌های JavaScript را منتشر کنید و کش فایل‌های ثابت را طبق روش جاری سایت تازه کنید. API تعیین کلاس برای وضعیت‌های قبلی سازگار است و وضعیت `ongoing` را نیز می‌پذیرد. وضعیت اداری ترم همچنان به ظرفیت هنرجو و مدرس وابسته است، اما دیگر به ایجاد جلسه وابسته نیست. ثبت هنرجو بدون تعیین کلاس و تاریخ، جلسهٔ تقویم ایجاد نمی‌کند؛ سرویس تقویم نیز جلسهٔ بدون کلاس را حذف می‌کند.

داشبورد برای هر ترم در حال برگزاریِ بدون کلاس، یک اقدام با شناسهٔ پایدار `term-classroom-{id}` تولید می‌کند؛ داده از محدودهٔ شعب مجاز همان کاربر خوانده می‌شود و در هر بار بارگذاری دوباره محاسبه می‌شود. تعیین کلاس، اقدام را از پاسخ بعدی حذف می‌کند. تغییری در جداول اقدام یا دادهٔ تاریخی ثبت نمی‌شود.

در Flutter فقط `lib/screens/Site/panel_resource_page.dart` و `lib/screens/Site/panel_dashboard.dart` تغییر کرده‌اند. API و وب باید پیش از انتشار نسخهٔ اپ به‌روز شوند. این تغییر به قابلیت‌های آزمایشی OMR یا پخش‌کننده‌ها وابسته نیست و قابلیت انتقال انتخابی دارد؛ `AGENTS.md` و تغییرات قبلی را منتقل نکنید.

بررسی‌ها: syntax چهار PHP و چهار JavaScript، تست‌های ثبت هنرجو، ظرفیت، زمان‌بندی و مرز آموزشگاه روی SQLite، تست جدید تعیین کلاس پس از ثبت هنرجو، و تست قالب داشبورد موفق بودند. تحلیل Flutter دو فایل تغییرکرده خطا نداشت. تست یکپارچهٔ MySQL و آزمون مرورگر روی سرور انجام نشده است.

۹ تست قرارداد فرم‌های Flutter نیز موفق شدند. بررسی سراسری `php-maintainability.php check` موفق نیست و چندین متد، از جمله سرویس داشبورد، از سقف پیچیدگی ثبت‌شده عبور می‌کنند؛ این بررسی مانع ادعای عبور کامل از چک‌های انتشار است.

آزمون پس از انتشار: ترم بدون هنرجو دکمهٔ حضور و غیاب و تعیین کلاس نداشته باشد؛ هنرجو را ثبت و دیالوگ کلاس را رد کنید؛ نبود جلسه در تقویم و وجود اقدام داشبورد را بررسی کنید؛ کلاس را تعیین کنید و حذف اقدام در بارگذاری بعد را ببینید. کاربر آموزشگاه دیگر نباید بتواند کلاس همین ترم را تغییر دهد.

بازگشت: همین فایل‌ها را به نسخهٔ قبلی بازگردانید؛ migration برگشتی لازم نیست. ترم‌های ثبت‌شده را حذف نکنید و تغییر وضعیت اداری ترم‌های ایجادشده در فاصلهٔ انتشار را بدون بررسی داده انجام ندهید.
