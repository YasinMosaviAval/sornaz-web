# کارت تمرین و دریافت کاتالوگ اپلیکیشن

فهرست عمومی API سرور اصلی هنگام بررسی این تغییر، ۱۰ بخش و ۲۲۴ آزمون داشت؛ این بررسی فقط خواندنی و بدون حساب کاربر بود. موفقیت درخواست عمومی، سلامت مجوز آفلاین یک حساب واردشده را اثبات نمی‌کند.

در API موبایل، نبود کلید امضای آفلاین دیگر دریافت تمام فهرست را متوقف نمی‌کند. ساختار و آزمون‌های مجاز دریافت می‌شوند و `offlineMessage` وضعیت آماده‌نبودن امضا را توضیح می‌دهد. مجوز جعلی یا کلید قابل حدس تولید نمی‌شود. ثبت نتایج موبایل همچنان امضای معتبر می‌خواهد و اجرای حساب واردشده بدون مجوز دانلود در اپ مسدود است.

اگر این پیام باقی ماند، مدیر میزبان باید مقدار تصادفی و پایدار حداقل ۳۲ نویسه‌ای `MUSIC_PRACTICE_SIGNING_KEY` را در تنظیمات خصوصی سرور قرار دهد. برای ساخت مقدار روی خود میزبان می‌توان از دستور زیر استفاده کرد و خروجی را فقط در فایل تنظیمات خصوصی نگه داشت:

```sh
php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"
```

کلید موجود معتبر را تغییر ندهید، `APP_KEY` را جایگزین نکنید و مقدار کلید را در Git، مستندات یا گفتگو نفرستید. پس از بارگذاری تنظیمات، OPcache طبق روش میزبان تازه و فهرست داخل اپ دوباره دریافت شود. تنظیم کلید سرور اصلی در این تغییر انجام نشده است.

Flutter ابتدا کش همان حساب را می‌خواند، پاسخ معتبر تازه را ذخیره و دوباره از حافظه می‌خواند. رفرش دستی خطای واقعی سرور را نشان می‌دهد. پاسخ نامعتبر جای کش سالم را نمی‌گیرد و کش خالی نمی‌تواند خطای درخواست را به پیام «هنوز آزمونی منتشر نشده» تبدیل کند. نتیجه‌ها، نسخه‌های دریافت‌شده و صف بارگذاری قبلی حفظ می‌شوند. عنوان اضافی در صفحهٔ اصلی آزمون‌ها حذف و از `HomeTopBar` مشترک همراه رفرش، آپلود و مدیریت استفاده شده است. کارت‌ها از ظاهر فهرست قدیمی و ستاره‌های مشترک و تمرین از انتخاب پاسخ و دکمهٔ بررسی استفاده می‌کنند.

در وب، دکمهٔ شروع همان کارت را به عرض ردیف باز می‌کند. پخش پرسش، پیشرفت، گزینه‌ها، انتخاب پاسخ، بررسی و بازگشت درون کارت هستند؛ تمرین به انتهای فهرست منتقل نمی‌شود. نمایش طبق تم سایت و حرکت کاهش‌یافتهٔ مرورگر است.

## انتشار وب

این تغییر migration ندارد. اصلاح قبلی [اجرای آنلاین وب](music-practice-online-web.fa.md) باید برقرار باشد. فایل‌های این تغییر به ترتیب:

۱. `Modules/Education/Services/MusicPracticeAccess.php` پیش از `Modules/Education/Services/MusicPracticeCatalog.php`؛ کاتالوگ جدید به متد تازهٔ Access وابسته است.

۲. `assets/Education/css/music-practice.css`، سپس `assets/Education/js/music-practice.js` و `Modules/Education/Resources/Views/music-practice.php`. نسخهٔ فایل‌های ثابت خودکار محاسبه می‌شود.

پیش از انتشار، نسخهٔ فایل‌های قبلی نگه داشته شود. برای بازگشت، همین مجموعه هماهنگ برگردد؛ CSS تازه را پس از برگشت view حذف کنید. دیتابیس و کلیدها نیاز به بازگشت ندارند. پس از انتشار، فهرست عمومی و حساب واردشده، دریافت مجوز موبایل، شروع/بررسی/بستن کارت در وب و رد نتیجه با امضای نامعتبر بررسی شود. درخواست مدیریتی کاربر فاقد مجوز نیز باید رد شود.

## آزمون‌ها

`node scripts/music-practice-online-test.cjs` سرویس واقعی با SQLite حافظه‌ای و رابط وب با HTTP شبیه‌سازی‌شده را بررسی می‌کند؛ دریافت فهرست بدون کلید، حفظ کنترل امضای موبایل و اجرای داخل کارت در فارسی/انگلیسی و عرض موبایل/دسکتاپ پوشش دارند. آزمون Flutter در شاخهٔ توسعه با `test/music_practice_test.dart` و `test/music_practice_validation_test.dart` انجام می‌شود. آزمون کاملِ دستگاه واقعی با حساب سرور اصلی هنوز لازم است.
